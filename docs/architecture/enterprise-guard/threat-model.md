# Enterprise Guard 威胁模型与覆盖层

> 版本：v1.0 · 最后更新：2026-08-28 · 负责人：Comet maintainers · 评审：Proposed（Issue #2）

## 保护目标

Enterprise Guard 保护企业 SDD Agent 日常执行中的高风险工具调用与普通 PR 违规：意外写入 `.env`、明文密钥、危险删除和受保护分支的强制推送。它提供确定性的规则结果、可过期的例外和可由 CI 复核的证据，而不是依赖 Agent 遵守自然语言提示。

## 三层覆盖

| 覆盖层       | 部署主体                   | 防护对象                                          | 强度与限制                                                                                                                   |
| ------------ | -------------------------- | ------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 项目级       | 仓库维护者                 | 正常使用项目配置的 Agent 与普通 PR。              | 配置与脚本在工作区内，可被具有写权限的主体修改；只能视为行为护栏。                                                           |
| 企业受管全局 | 企业 IT/MDM/管理员。       | 受管设备上的 Agent 调用。                         | 必须由平台的系统、MDM、云策略或等效不可由用户关闭的配置实际承载。`comet --scope global` 的用户配置安装不等同于企业受管全局。 |
| CI 兜底      | 远端仓库与分支保护管理员。 | 所有 PR、直接推送和本地 Hook 被绕过后的代码状态。 | 不在工具调用前阻断本地动作，但可在合并/部署前可靠拒绝违规。                                                                  |

三个层必须并存：项目级缩短反馈，企业受管全局降低本机绕过，CI 兜底提供可审计的远端事实源。任何一个项目级 Hook 都不能取代受保护 CI。

## 对手与处置

| 情景                                                    | 预期处置                                                                     |
| ------------------------------------------------------- | ---------------------------------------------------------------------------- |
| Agent 无意写入 `.env`、密钥、危险删除或 force push      | 在支持同步阻断且已验证的平台由 HARD 规则拒绝；其他平台记录诊断并由 CI 检查。 |
| 普通贡献者绕过项目说明或遗漏本地 Hook                   | CI 在 PR/受保护分支上重新评估规则与例外。                                    |
| 普通贡献者提交伪造的“已批准”文本                        | 无效；只有独立、受保护的例外记录连同审批和 CI 证据可被读取。                 |
| 用户关闭本地 Hook 或修改项目 Hook 配置                  | 项目级保护失效；受管全局或 CI 必须承担保护责任。                             |
| 能修改本地 Hook、安装文件、规则文件或本地 CI 的恶意主体 | 不属于本能力的抵御范围。                                                     |
| 能修改企业 MDM、系统策略或远端分支保护的管理员级主体    | 不属于本能力的抵御范围，需要组织级身份、审计与变更控制。                     |

本能力不抵御能够修改本地 Hook 或安装文件的恶意主体。文档、安装器和后续实现都不得把本地文件完整性宣称为对该主体的安全边界。

## 信任与数据处理边界

- Hook 输入可能含有命令参数、文件内容和凭据。标准化器必须按输入契约保留截断事实，并在日志与规则证据中脱敏。
- 平台原始 JSON 是前向扩展输入；未知字段可被保留为摘要，但严格解析器不能因忽略新字段而把关键字段缺失解释为安全。
- 每次规则结果应带规则 ID、版本、决策原因和最小必要证据。审计系统保存摘要与哈希，不保存原始秘密。
- 例外记录与规则目录是策略资产，必须由受保护分支、CODEOWNERS 或等效审批机制维护；它们不能随普通业务代码自由修改。

## 实施前检查

后续实现 Issue 在把某个平台提升为 HARD 阻断前，必须完成平台矩阵中定义的最小 Spike，验证输入 JSON、并列 Hook、阻断/超时、安装生命周期和诊断。若 Spike 发现 fail-open、可禁用 Hook 或不可验证安装位置，覆盖等级必须降为 CI 兜底。
